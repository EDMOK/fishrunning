## 1. 一句话

**运行时不再发明几何。** 它只做三件事：选段、拼段、控节奏。几何由离线构建器批量生成、逐条验收、策展后冻结；运行时回放的每一块都是已经被证明过的那一块。

---

## 2. 为什么改

改造前，跑道几何由四条路径在运行时现场生成：

| 来源 | 位置 | 问题 |
| --- | --- | --- |
| 基础模式（25 个） | `game.js` 内的 `PATTERNS` | 与共享编排互不知情 |
| 共享编排（29 个） | `route-patterns.js` | 同上 |
| 动作连段（8 个） | `action-routes.js` | 绕过导演、锁速、从未被审计 |
| 事件临时障碍 | `game.js` 的 `safeHazardSlot` | 只检查"有没有重叠" |

三个后果：

1. **验证只能抽样，且抽样对死局天然失明。** 要证明的是"随机几何 × 连续到达状态（空中/滑铲/剩余跳跃）× 连续机关相位"整个空间里不存在死局，这是连续空间上的 ∀∃ 问题，枚举不完。
2. **`speed` 是全局量，有四个写入方**（基础曲线、相位乘数、事件乘数、动作块锁速）。任何一处改动都会移动后面所有段落的实际间距与跳跃弧线。同一颗随机种子两次跑出 674 与 925 的"速度回退"，来源就在这里。
3. **三套系统各自表达"间距"，口径不同。** 模式用 `speed * react + 150`（时间域），动作连段用 `q = sqrt(320*speed)`（长度域），事件用硬编码的 `92`。

冻结之后，证明义务从"所有可能的组合"塌缩成"每一条已冻结的段"，而且每条只需要在它自己的波段速度上被证明一次。

## 3. 段落契约

`src/run-segments.js` 定义字段，`DSRunSegments.normalize()` 保证缺省安全。本轮新增两个关键字段：

```js
{
  speed,    // 本段锁定的速度；冻结段 = 波段速度，动作连段 = block.speed
  runway,   // 段尾恢复跑道 { from, to, fromSpeed }，不可侵占
  variety,  // 本段包含多少种不同障碍（由 chunks.js 计算）
  hazards,  // 本段障碍总数
}
```

### 速度契约：段内锁死，跑道缓动

```
段内      speed = 段.speed
跑道内    speed = fromSpeed + (自然曲线 - fromSpeed) * ease    ease = 段内进度 0..1
其它      speed = 自然曲线 = speedAtRun(dist, runElapsed) * mulOf('speedMul')
```

**没有任何随机事件乘数能伸进段内。** 事件的 `speedMul`（0.7 ~ 1.45）现在只在跑道缓动里体现，因此不会把一个正在被阅读的段落改形。

### 跑道的口径：`x + w + motion`

净空区间的起点一律按**实际摆放实体的扫掠范围**计算，不能用标称预留值，也不能只用美术宽度：

- 事件墙曾按硬编码 `92` 起算，而 `crystals` 美术宽 `96` —— 4px 的障碍尾巴留在"净空"里。
- 会摆动的障碍（`motion`）扫掠范围超出美术宽度，不计入则摆动端甩进跑道。

现在四处统一：事件墙跑道起点、验证条跑道起点、chunk 的 `len`、运行时段的 `xEnd`。

### 自省面的帧相位

`DSGame.world()` 里：

- 标量按值返回，**数组按引用返回**（`obstacles/platforms/gaps/segments/runways` 都是活引用）。验证器跨帧混读会得到两帧拼接的结果。
- `segmentX` 是**做段判定那一帧**的玩家世界坐标。相机在同一帧稍后才推进，所以 `camX + PLAYER_X` 会早一帧（最高速下 2.85px）。
- `speedSource`（`practice/action/pattern/runway/natural`）、`speedEase`、`speedNatural` 让验证器可以**核对游戏声明的来源**，而不是自己重算聚合值——重算的验证器只可能和自己吵架。

## 4. 离线段库

### 构建流水线（`tools/build_chunks.cjs`）

```
滚大量候选  →  硬门限筛除  →  打分排序  →  按多样性挑选  →  冻结
```

- 手写模式每组合滚 220 次；语法组合滚 40~90 次（它们有几百个兄弟，不需要每个都深挖）。
- 波段：**380 / 520 / 700 / 900**。运行时取**最近波段**（不是容差内的全部），否则自然速度 490 时可抽到 380 的段，玩家会感到 110px/s 的突兀阶跃；最近波段把阶跃限制在半间隔内，再由跑道缓动吸收。
- 速度阶跃由跑道的 1 秒缓动吸收，所以波段间距可以大于单段容差。

### 硬门限（`tools/lib/chunk-audit.cjs`，构建与审计共用同一份实现）

| 门限 | 内容 |
| --- | --- |
| 平台可达性 | 用跳跃物理做最早到达搜索，必须在 `0.7x / 1x / 1.45x` 波段速度下都能从入口走到出口 |
| 地面障碍净空 | 单次跳跃弧线必须覆盖障碍宽度 |
| 坑规则 | 地面障碍不得落进坑，两个地面障碍不得共享地面 |
| 平台规则 | 同高平台不得互相穿插 |
| 米的可达性 | 米不得埋进障碍；坑上方的米必须在跳跃可达高度（约 y ∈ [250, 606]）或平台支撑上 |
| 起点规则 | 几何不得越过段起点（段前净空由上一段的跑道保证） |
| 弹簧规则 | 含弹簧的段必须存在 `y ≤ 258` 的平台（二段跳天花板）——见下文 |

**物理常量会对账**：`chunk-audit.cjs` 的 `GRAVITY / JUMP_V / FALL_MUL / PLAYER_BOX_W / CLEAR_SLACK / GROUND_Y / DJUMP_V / DJ_RISE_G` 以及弹簧初速（从 `game.js` 的弹起处理行正则读取）由 `verify_chunks.cjs` 与 `src/game.js` 逐一对读，不同步直接失败。这条机制写出来的当下就抓到了自己漏导出 `FALL_MUL`。

### 质量分

死区占比、family 密度契合、障碍种类与平台高度多样性、节奏规整度（地面障碍间距变异系数）、安全余量、长度合理性。

### 多样性挑选

同组变体之间用 **Jaccard 距离**（签名按 32px 量化，含障碍种类/位置/摆动、平台、坑、米），逐级放宽 `0.34 → 0.06`，贪心取高分者。

## 5. 组合节拍（`tools/lib/combo-patterns.cjs`）

**这是本方案里唯一一种会在一拍里放多个障碍的生成器。** 其余所有生成器都是"一拍一个障碍"，所以只冻结它们，玩家看到的仍然是单障碍列表——"随机组合"不会因为上了段库就自动出现。

### 语法而非模板

模块表：`hop`（跳跃）/ `tall`（高障碍跳跃）/ `duck`（下滑）/ `gap`（跳坑）/ `gift`（下滑带奖励）。序列长度 2~4，长度 4 的均匀抽样 72 个，共 **246 个源**。

`buildFrom(seq)` 按顺序放置模块，间距只取决于**上一个模块用掉的动词**：

| 转换 | 最小间距 | 物理原因 |
| --- | --- | --- |
| 跳 → 跳 | 1.15u | 完整弧线 + 落地 + 读下一个 |
| 跳 → 滑 | 1.60u | **空中按下是快落**，滑铲只能在落地后开始 |
| 滑 → 跳 | 0.90u | 松手即可起跳 |
| 滑 → 滑 | 0.95u | 连续两段滑铲 |

`u = 320k`，`k = sqrt(speed*0.7/320)` —— 与运行时编排同一套 reserve。一次平跳覆盖约 0.84u。

**同一拍内强制用不同障碍种类**（`used` 集合）：第二次跳跃不再抽同一种障碍，否则"跳两次"只是节奏而构不成组合。

## 6. 奖励轨迹（`src/reward-shapes.js`）

奖励曾经只有"直线"和"单弧"两种形状，所以每条米带看起来都一样。现在有 10 种形状，每次随机抽形状 + 高度 + 振幅，且不连续重复同一形状：

```
arc 单弧    wave 多周期波浪   zigzag 折返     stair 阶梯
vee 谷      peak 峰           bounce 弹跳     ladder 交替高低
comet 彗尾   ridge 高原（平顶陡肩）
```

效果：含米的段里有 **2166 种不同的高度剖面**（2823 条采样）。`glide-trail` 固定用 `ridge`（平顶正是滑翔买到的东西），`rush-ribbon` 保持直线（风险带的价值在于不断线），但它的诱饵轨迹每拍换形状。

## 7. 导演规则（`game.js`）

`RouteDirector`（`route-patterns.js` 的 `choose`）继续负责 family、近期重复、节奏相位与教学权重。在此之上新增四条运行时规则：

| 规则 | 内容 | 解决什么 |
| --- | --- | --- |
| **布局防重复** | `recentChunks`（窗口 4）按 `chunkId` 过滤 | 同一块布局不再连着重现 |
| **节拍防重复** | `recentPatterns`（窗口 5）按**基名**过滤 | 导演自带机制；两者必须用各自的键 |
| **休息不连续** | 无威胁拍之后，下一拍必须有威胁（`restStreak` / `hazardDrought`） | 连续纯奖励段造成的"大空地" |
| **组合下限** | 单障碍拍之后，下一拍非奖励拍必须是组合（`needVariety`） | 权重只能决定平均，规则才能决定下限 |

**权重与保证必须同时存在。** 组合节拍多为 `mixed` 类，而 `mixed` 在 0~2 阶权重只有 ×0.8，奖励 ×2.2、平台 ×1.55 —— 只把组合放进池子会被权重系统性压下去。因此段自带 `weightBoost`（2 种障碍 ×2.4，3 种以上 ×3.2），并由 `needVariety` 给出概率下限。

## 8. 长段补威胁（dresser）

手写的平台/断口段是最长的内容（`islands-stairs` 平均 1971px、`islands-valley` 1914px），且完全不包含障碍。构建器对超过 800px 的段补 1 种障碍、超过 1600px 补 2 种，只放在实地上，避开平台边缘、坑、已有障碍、以及段的入口与出口（入口出口归跑道契约管）。注入的障碍会带上米弧，读作"跳我"而不是"这里掉了个东西"。

## 9. 本轮修掉的缺陷清单

按发现方式分类，**这是本次改造中价值最高的部分**。

### 由新验证器抓出

| 缺陷 | 症状 | 根因 |
| --- | --- | --- |
| 动作连段尖刺带不可解 | 玩家截图报"完全过不去" | 带宽 0.70q，而单跳最多覆盖 0.6535q —— **任何速度都过不去**；动作连段此前从无审计 |
| 动作连段坑无落点余量 | 同上 | 坑宽 0.70q，只比平跳的 0.836q 少一点 |
| 动作连段"跳→滑"间距不足 | 同上 | 床到低顶 0.66q，最晚落地后只剩 0.11s 按下滑 |
| 弹簧无意义 | 玩家质问"平地放弹簧干嘛" | 弹簧初速 1120 → 285px，**低于"单跳+二段跳"的 342px**，平地上永远不是必需品 |
| 事件墙跑道起点差 4px | 跑道侵占检查报警 | 硬编码 92 对 crystals 美术宽 96 |

### 由覆盖面断言抓出

| 缺陷 | 症状 | 根因 |
| --- | --- | --- |
| `turret/gate/sentry` + 4 个动态机关段整组消失 | 三分之一的素材永不出场，而**所有几何检查全绿** | 冻结时只包含了共享编排，漏掉 `game.js` 自带的 25 个基础模式 |
| `sentry` 在库中缺失 | 同上，由覆盖面断言直接点名 | 同上（覆盖面断言的第一个战果） |

### 由"假多样"检查抓出

| 缺陷 | 症状 | 根因 |
| --- | --- | --- |
| 123 组"多变体"是同一条布局的复制品 | 库有条数、有分数分布、门限全绿，但变体数 ≈ 组数 | `capture()` 返回共享数组的**引用**，而 `serialize()` 在整批滚动结束后才执行 |
| 单障碍短拍被误杀 | `single`/`tall` 全波段零产出 | "太短"下限 200px 砍掉了合法的单障碍节拍 |
| `cloud-bridge@900` 越界 | 平台起点算到负偏移 | 高波段的 k 变大后 `start - 70*step` 越过原点，侵占上一段跑道 |

### 由运行时探针抓出

| 缺陷 | 症状 | 根因 |
| --- | --- | --- |
| 导演防重复彻底失效 | `rush-ribbon` 一段独占 15% 的跑局 | 导演按 `p.id` 判断，我却推进 `chunkId`，两边对不上，过滤变成 no-op |
| 休息规则反向 | 开局连出四个纯奖励段 | 过滤条件写成 `!p.hazards`（放行无威胁段），应为 `p.hazards > 0` |
| 组合被权重压制 | 玩家"完全感受不到组合" | 见 §7：池子配比 + family 权重反向拉 + 无概率下限，三层叠加 |

### 由验证器自身的修正抓出

| 缺陷 | 症状 | 根因 |
| --- | --- | --- |
| "速度不回退"断言不稳定 | 同种子两次跑出 674 与 925 | 断言把"难度相位递增"和"事件乘数/段锁速"混为一谈；且验证器先步进 600 帧再从同一快照读标量（旧值）与数组（实时值） |
| 常量镜像漂移 | `verify_chunks` 当场失败 | `chunk-audit.cjs` 漏导出 `FALL_MUL` |

## 10. 验证体系

| 工具 | 证明什么 | 速度 |
| --- | --- | --- |
| `tools/verify_chunks.cjs` | 库中每条重放并重跑硬门限；同组变体几何两两不同；每种障碍素材与动态机关都有段摆放；物理常量与源码对账 | 秒级，无浏览器 |
| `tools/verify_action_routes.cjs` | 8 个动作连段 × 12 档速度（330~1500）的几何可达性、屋顶强制滑铲且不刮到滑铲、平台路线可达 | 秒级 |
| `tools/verify_chunk_runtime.cjs` | 浏览器内：速度三态与游戏声明一致、跑道零侵占、库已加载、回放真的产出实体且带已解码美术 | ~30 秒 |
| `tools/verify_dynamic_hazards_browser.cjs` | 完整 190 秒回归：动态机关判定、暂停冻结、速度契约、跑道完整性 | ~3 分钟 |
| `tools/measure_variety.cjs` | 库构成（按波段×阶）与真实跑局的逐拍统计 | ~1 分钟 |
| `tools/inspect_chunk.cjs` | ASCII 侧视图，肉眼验收单块布局 | 即时 |
| `tools/probe_chunk_sequence.cjs` | 一段跑局的完整段落序列与重复直方图 | ~1 分钟 |

## 12. 复现

```bash
node tools/build_chunks.cjs          # 物化段库（确定性种子 20261007）
node tools/verify_chunks.cjs         # 离线审计 + 覆盖断言 + 常量对账（秒级）
node tools/verify_action_routes.cjs  # 动作连段几何审计（秒级）
node tools/verify_chunk_runtime.cjs  # 30 秒运行时契约快检（需 127.0.0.1:8123）
node tools/measure_variety.cjs 150   # 库构成 + 跑局逐拍统计
node tools/inspect_chunk.cjs combo-gauntlet-plus --band 900   # ASCII 侧视图
```

浏览器验证器需要先起服务：

```bash
python -m http.server 8123 --bind 127.0.0.1
```

**改了任何生成器之后必须重建段库**，否则新内容不会出现在运行时，且**不会报错**——这是本项目最容易踩的静默失败。
