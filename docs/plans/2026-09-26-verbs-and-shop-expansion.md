# 白饭大冲刺 · 新操作与商店扩充记录

日期：2026-09-26
状态：已实现；离线平衡证明与浏览器实测通过，长时自动跑覆盖 1484m

## 已确认需求

1. 商店道具种类与价格都要增加。
2. 玩法不能只有跳和下滑，要增加更多互动操作与可玩性组合。

## 一、三个新动词

原有动词只有跳 / 二段跳 / 滑铲 / 空中快落。新增三个，都有独立的输入、独立的收益与独立的
代价，且都能和旧动词串联（跳→滑翔→冲刺→踩碎→弹起→二段跳）。

| 动词 | 输入 | 触发条件 | 效果 | 代价 |
|---|---|---|---|---|
| 冲刺 Dash | `Shift` / `J` / 触屏右滑 | 有充能且不在冷却 | 0.34s 内地面推进 ×1.9、撞碎可破坏障碍、结束时 0.2s 宽限无敌 | 每格充能 2.6s 回复 |
| 下砸 Stomp | 空中按住 `↓`（沿用快落） | 下落中从上方接触可破坏障碍 | 踩碎（障碍真的消失）、弹起、连踩递增奖励 | 落地清零连踩数 |
| 滑翔 Glide | 长按跳跃键（过顶点后） | 体力未耗尽 | 下落重力 ×0.22、终端速度封顶 | 体力 0.9s，落地才回满 |

### 不能违反的边界

- **冲刺绝不改 `speed`**。`speed` 同时喂 `jumpK()`（跳跃弧线形状）、`gapFor()`（关卡生成器
  实时读取的间距）和音频强度。改它会让冲刺期间的生成间距变稀、跳跃弧线变形。
  新增局部量 `travel = speed * dashTravelMul`，只用于 `camX` / `dist` / 随之而来的得分。
  （近失判定用的是 `speed * dt`：冲刺期间近失本来就被跳过，写 `travel` 只会是一句假的注释。）
- **只有 `bug/spike/usb/error/server` 可被撞碎或踩碎**。`token`/`tower` 是必须跳的高障碍，
  浮空障碍（`bob`）保持纯滑铲威胁，`eventHazard`（事件墙、验证条）是刻意设卡 —— 三者全部豁免，
  否则冲刺会变成一路平推。
  这条闸门在**冲刺期间**和冲刺结束的宽限期内都必须生效。代码评审抓到过一个真实漏洞：
  最初写成 `player.dashT > 0 || (player.dashGrace > 0 && breakable(o))`，括号位置让冲刺本体
  绕过了 `breakable()`，0.34 秒内可以把 `tower` 一起撞碎 —— 与注释和设计正好相反。
  现在两段都走 `breakable()`，A/B 实测：可破坏目标 + 冲刺 → 碎裂（`shieldBreak` 音效、不掉血）；
  `tower` + 冲刺 → 不碎、走正常受伤流程。
- **踩碎必须真的移除障碍**。`tryStomp` 一开始只弹起、不置 `o.dead`，于是「踩碎!」的字样和
  提示文案都是假的，障碍还立在身后。现在三个动词共用 `shatter(o, opt)`：障碍出局、碎片、飘字，
  `opt` 只承载三者真正不同的部分（措辞、命中点、配色、是否自己放音效）。
- **弹起不给满血二段跳**。`player.jumps = min(jumps, 1)`，否则「踩一脚 + 满血二段跳」可以跳过
  生成器放在两者之间的任何编排。连踩上限 3 段。

### 滑翔与既有难度证明的关系

`tools/verify_balance.py` 第 2/2b 节证明的是「最坏情况二段跳也会落在两块编排之间的空地上」。
滑翔是有意延长滞空，所以它**不在那条保证里**，而是被单独约束：

- 体力上限 `GLIDE_MAX = 0.9s`（满级 1.57s），实测封顶生效（浏览器采样 maxGlide = 0.908）。
- 按 `↓` 立即取消并转入快速下落 —— 工具新增 2c 节直接 grep 源码里的 `!downHeld()` 与 `GLIDE_MAX`，
  这两个词消失就报 FAIL。「随时能下来」是源码性质，不是这组数字能重算出来的。
- 2c 节并排列出「滑翔多买的滞空距离 vs 一块编排 + 间隙的距离」：以基础体力算约为一块编排的
  一半，属于玩家主动放弃该段白饭换取跨越，不是无代价。

## 二、新编排（全部仍可单跳清除）

三个教学编排，各自只奖励对应动词，但用旧动词也过得去：

| 编排 | min tier | 构成 | 为什么这样排 |
|---|---|---|---|
| 踩踏链 | 2 | 3 只 bug，间距 320px | 320−57 > CHAIN_GAP(240)，各自成簇；一次弹起只前进约 91px，够不到下一只，所以连踩需要「弹起+二段跳」的组合 |
| 滑翔长弧 | 1 | 高空 9 颗白饭长弧（dx74）+ 地面安全线 | 无障碍物，所以长滞空没有可越过的危险，不会破坏难度 |
| 冲刺走廊 | 3 | 1 个 usb + 一条穿过它的低位风险线 | 跳过去就丢掉风险线，跑过去要吃一次伤害，冲刺全收 |

**踩过的坑**：最初踩踏链与冲刺走廊用了 300px 间距。`CHAIN_GAP` 是从**碰撞盒边缘**算的，
bug 的盒子相对美术内缩 57px（usb 内缩 83px），所以 300px 实际只有 185px 的空隙，
两个障碍被判成同一簇，`clearSpan` 直接给出 −178px 的不可清除结论。
`verify_balance.py` 第 3 节当场拦下，间距改为 320px 后通过。第 3 节原先还在验证早已不存在的
`spike/spike` 双障碍，这次一并按 `PATTERNS` 实际情况重写。

## 三、商店：4 项 → 9 项

价格分档依据：一局白饭收入约每 1000 米 220–260。全部买满约 860 白饭，
所以一局只够买通一两条流派 —— 这是有意的取舍，不是买空商店。首级压在 10–20，开局就能买到东西。

| 技能 | 流派 | 效果（每级） | 价格 |
|---|---|---|---|
| 缓存命中 | 收益 | 连击窗口 +0.3s | 10/18/30 |
| 白饭优化 | 收益 | 白饭收益 +8% | 12/20/34 |
| 滑动窗口 | 机动 | 二段跳高度 +4% | 14/24/40 |
| 算力调度 | 强化 | 道具时长 +8% | 14/24/40 |
| 评分加权 | 收益 | 得分 +8%（新增 `scoreMul` 技能） | 16/28/46 |
| 流式滑翔 | 机动 | 滑翔体力 +25% | 16/28/46 |
| 压栈下砸 | 机动 | 踩踏弹跳与得分 +15% | 18/32/52 |
| 并行冲刺 | 机动 | 冲刺充能 +1 格 | 20/34/56 |
| 冗余副本 | 强化 | 立即 +1 条命 | 35/60/95 |

实现要点：

- **没有做 `stats[]` 数据模型迁移**。只有冲刺想要两个轴，直接给它单轴 `dashAdd`、冷却固定，
  `mulOf/addOf/auditContentTags` 一行未改，只往 `KNOWN_MULT` 加了 `glideMul/stompMul/dashAdd`。
  漏登记的症状是「技能买了没用，控制台一行警告」，所以这是最该少动的地方。
- **`lifeAdd` 走即时通道**：`buySkill` 读 `skill.onBuy` 交给既有的 `fireInstantTag`，
  全项目仍然只有一处「加一条命」的实现。
- **顺带修掉一个既有 bug**：`buildLives()` 固定造 3 颗心，命数超过 3（合规边境的 `lifeAdd` 早就能
  触发）时第 4 条命根本显示不出来。现在心数按 `game.lives` 增长，失去的心保留为暗色。
- 折扣事件从「抽 1–2 项」改为「抽 2–3 项」：9 项里只有 1 项打折太容易错过。
- 等级圆点循环上限由写死的 3 改为 `skill.costs.length`。

### 内容审计的覆盖范围

`auditContentTags()` 原先只看 `s.stat`，而新商店有三类**不走 `mulOf/addOf`** 的字段，
每一类都会以不同方式静默失败：写错的 `onBuy.tag` 永远不触发、写错的 `tag` 会退化成默认配色、
写错的 `glyph` 会画出一张空图标。现在启动审计同时检查这三个字段。
实测有效：故意把 `lifeAdd` 写成 `lifeAd`、`收益` 写成 `收溢`、`chart` 写成 `chartt`，
控制台一次报出全部三条（`category "收溢" (shop:score), glyph "chartt" (shop:score), lifeAd (shop:life.onBuy)`）。

### 新图标不落盘

冲刺/下砸/滑翔/得分四个图标没有美术文件，改为启动时用 canvas 画一次、
以 data URL 供商店 `<img src>` 使用；超频道具图标则用 `tint()` 把芯片图染成金色。

**为什么不加进 `PATHS.item`**：`loadAll()` 对非可选类别是「缺一张就 reject 启动」，
加新条目就必须往仓库塞真 PNG。另外 canvas 没有 `naturalWidth`，
`drawPickups/drawPowerups` 的取尺寸处已改为 `naturalWidth || width`。

## 四、新道具与 HUD

- 新增世界内道具 **超频（Overclock）**：8 秒内得分 ×2（受 `powerMul` 延长）。
  刻意**不带白饭倍率** —— 带的话就是变相刷经济。
- 得分倍率收敛到单一入口 `scoreMul()`（= `mulOf('scoreMul')` × 超频 ×2）。
  跑动得分、险过、踩踏、冲刺撞碎、白饭分全部走它，否则「得分翻倍」只会半生效。
  风险线 +60、分区目标 +60 保持定值 —— 玩家把它读作固定数字。
- 冲刺充能单独一个 `#dashHud` 面板，**不放进 `#powerups`**：后者是按 key 签名整块重建的，
  放进去会被反复清空。
- 道具条上的文字标签由 `POWER_INFO[k].label` 填进 DOM（`textContent`），不再用 CSS
  `content:"..."` 逐条硬写 —— 加一个道具从「改 JS + 改 4 条 CSS」变成只改内容表。
- 充能补发走 `topUpCharges()`，`update()` 与 `buySkill()` 都调用它。商店打开时 `update()`
  是被冻结的，只靠每步补发会让刚买到的充能在商店里显示成「已用完」，直到关闭商店才补上。
- 滑翔体力条画在画布上、角色脚下，只在滞空且体力未满时出现 —— 玩家是盯着角色决定
  「还够不够跨过这个缺口」的。

### HUD 遮挡问题（用户反馈）

`#dashHud` 加进右上角竖列后，该列从 18–117px 长到 18–175px，而 `#powerups` 仍被钉在
`top:140px`，于是超频条压在商店按钮上。修法不是再调一个魔数，而是把 `#powerups` 移进
`#topright` 的流式布局；`#shopNotice` 同样有固定 top，一并挪到右下角空地（那里没有任何常驻元素）。

实测各块边界（1280×720 逻辑坐标）：血量 18–74、冲刺 84–117、按钮 127–175、
道具条 185–428、特价提示 680–702，互不相交。

## 六、验证记录

- `node --check src/game.js / src/memes.js / src/audio.js`：通过。
- `python tools/verify_balance.py`：PASS。第 1/2/2b 节数值未变（旧保证仍成立），
  2c 节输出滑翔滞空预算并断言源码里的取消条件仍存在，第 3 节覆盖新增三编排。
- 浏览器（`python -m http.server 8123`）实测：
  - 冲刺：按键触发后 `dashT=0.34`、充能 0、冷却 2.6s；冷却中再按被拒；充能条按剩余时间推进
    （0.46s 时 82%）。
  - 下砸：空中按住 ↓ 踩碎 bug 并弹起，`stomp` 音效触发；自动跑累计 13 次踩踏、
    `maxChain=1`（链式需要「弹起+二段跳」的时机，自动脚本够不到）。
  - 滑翔：长按跳跃到顶点后 `gliding=true`，体力封顶实测 0.908s（= `GLIDE_MAX`）；
    按 ↓ 立即取消，`vy` 由 142 跳到 1427 转为快速下落。
  - 商店：9 张卡、价格按等级递进（35→60→95、20→34→56）、买`冗余副本`后心数 3→7、
    买`并行冲刺`后充能格 1→2、白饭正确扣减（924−35−60−20=809）。
  - 输入：右滑触发冲刺且不再附带跳跃（`buffer` 被清 0）；下滑触发滑铲（60ms 后
    `sliding=true`）——**这是顺带修好的**：原先 pointerdown 会先排一个跳跃，导致下滑
    先跳再铲；现在手势识别会丢弃那个未消费的跳跃缓冲。
- 长时自动跑（高命模式单局 1228m）：10-11 种编排全部生成过（含踩踏链、滑翔长弧、冲刺走廊），
  三个提示全部触发过（`DSGame.hints().seen`），14 次踩踏、4 次冲刺，
  `DSGame.audit()` 全程为 0，控制台无错误、无 `[content] unknown effect tag` 警告。
- 三个新动词的语义边界逐条验证：冲刺撞可破坏目标 → 碎裂且不掉血；冲刺撞 `tower` → 不碎、
  正常受伤；踩踏 → 障碍消失（同帧 `stomp` 音效 + 目标出局）；滑翔 → 体力封顶 0.908s、`↓` 立即取消。
- 为此在既有的只读 `DSGame` 自省钩子上加了 `patternCounts()` 与 `hints()`：
  「某编排从没被抽到」和「某提示没触发」原本从外部完全看不出来，只能靠反复跑碰运气。
  为此给每个 `PATTERNS` 条目加了稳定 `id`，统计结果按 id 取名（`glide-trail: 3` 而不是
  `9: 3`），否则外部脚本还得自己维护一张下标表。

### 顺带发现的一处既有不一致（已证明安全，未改行为）

`OBS_MIN_TIER` 声明 `error`/`server` 最早出现在 tier 2，但它们所在的 `TIER2` 池从 tier 1
就能被 `obstaclePool()` 抽到 —— 声明与行为不一致，而唯一读这个表的 `legalAt()` 根本没有调用点。
实测在 tier 1（386px/s、比声明的 469px/s 慢）两者仍然可跳过，但 `server` 只剩 **+18.8px**
余量，是全游戏最紧的一个。

没有去改 `obstaclePool()`：那会让 tier 1 变简单，属于用户没要求的难度改动。
改为把这个真实约束写进 `verify_balance.py` 的**新增第 1b 节** —— 它按 `TIER1/2/3` 与
`obstaclePool()` 的实际语义算出每种障碍「真正能出现的最早 tier」，再验算可跳过余量。
这样以后谁动了 tier 表或障碍高度，工具会立刻报警，而不是让一条注释悄悄失效。

## 遗留与未覆盖

- 触屏手势只做了合成 PointerEvent 验证，没有真机触摸测试。
- 连踩只自动复现到 2 段（`stompChain = 2`）；3 段的完整链条没有被脚本稳定复现。
  数值上弹起高度够得着下一只 bug（弹起前进约 91px，间距 320px，需配合二段跳），
  但要踩中时机，人工试玩比脚本更可靠。
- 长时自动跑是「无敌模式」，因此没有覆盖「连续失误下新动词是否让局面更难挽回」；
  设计上三个新动词都不消耗生命，冲刺结束有 0.2s 宽限无敌，风险应低于收益。
- 白饭收入按 500/1000/2000 米的分段实测尚未做，价格依据的是编排表推算（每 1000 米 220–260）。
  若实测偏差超过 30%，价格应重排并在此处记录新依据。
