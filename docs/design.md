# 《白饭大冲刺》整体设计背景

状态：设计文档。记录「明亮 AI 城市」重构的方向、依据与分期计划。
当前实现仍是暗色赛博风；本文是改造的基准，实施进度以 `docs/plans/` 里的计划文件为准。

## 为什么要改

现有画面的问题是气质冲突，不只是亮度问题：

- 暗色赛博朋克（深蓝面板、霓虹描边、CRT 扫描线、电路地板）与 Q 版拟人角色不搭，
  可爱角色被丢进了一个冷硬严肃的世界；
- 视觉主题围绕「鲸鱼 / 海洋」打转，而游戏真正讲的是 AI 与普惠；
- AI 味过重：紫色渐变、发光描边、网格地板，正是最典型的 AI 生成视觉指纹。

结论：世界观和界面都应该**围绕 AI 展开，而不是围绕角色本体展开**。
鲸鱼娘是主角，不是装饰主题。

## 设计定位：明亮的 AI 公共城市

> 一座正在运行、正在建设的 AI 城市：数据在天空中流动，算力是公共设施，
> 开源是市集，安全是灯塔。主角在这座城市里跑。

气质目标：**可爱、明亮、有技术理性但不冷硬**。
要避免两种失败：丢掉 AI 感变成普通糖果跑酷；或者回到冷金属发光那一套。

### 色彩系统

| 用途 | 颜色 | 说明 |
|------|------|------|
| 环境主色 | 天空蓝 / 云白 | 晴朗天空、云层，替代深蓝夜空 |
| 界面底色 | 奶油白 / 浅米 | 面板像纸张与卡片，而非金属 |
| 交互色 | AI 蓝 | 按钮、链接、可交互元素 |
| 奖励色 | 算力黄 | Token 白饭、分数、奖励 |
| 协作色 | 开源绿 | 增益、安全、社区类元素 |
| 危险色 | 珊瑚红 | Bug、错误、障碍，柔和但可辨识 |

规则：同屏只允许一个主强调色发光；阴影用背景色的深色调，
不用纯黑；禁止大面积暗色区块破坏整体亮度。

### 视觉元素清单

属于 AI 城市的元素（优先使用）：

- 模型节点网络：天空中的节点与连线，作为远景与装饰母题；
- 数据卡片、代码便签、Prompt / LLM / Agents 信息牌；
- 浮空平台（云端计算层）、轨道与交通线；
- Token 白饭、数据卡、推理火花等收集物；
- Bug 弹窗、错误警告、限流门等拟人化故障。

鲸鱼元素仅保留在 DeepSeek 娘本人与品牌徽记上，不扩散到赛道和界面。

## UI 与 HUD 原则

参考图提供的是**布局与信息层级**参考，不是视觉风格参考。采纳其结构：

| 区域 | 内容 |
|------|------|
| 左上 | 角色头像、生命、当前分区名 |
| 顶部中央 | 分数、距离、连击倍率、当前任务进度 |
| 右上 | 资源计数（白饭 / 数据卡 / 开源碎片）、技能与增益、暂停 |
| 左侧中部 | 本区任务卡（目标与进度） |
| 右侧中部 | 事件提示（升级、过载、奖励、捷径） |

要求：

- 计数面板要一眼可读：数字用等宽数字（`tabular-nums`）与独立底板；
- HUD 不遮挡关键落点与平台路线，移动端底部控制区沿用现有布局；
- 逻辑与渲染解耦：游戏状态先进统一的 `hudState`，再同步到 DOM，
  禁止散落的直接 DOM 操作。

## 赛道与平台（核心玩法重构）

现状：世界只有一条 `GROUND_Y = 600` 的地面线，角色固定在 `PLAYER_X`，
障碍全是贴地 AABB。浮空平台需要的不只是素材，而是一套新系统。

### 平台数据模型

```js
{ x, y, w, h, type: 'ground' | 'floating', oneWay: true, style: 'city_platform' }
```

第一版只做三种平台：地面、低空浮空平台、高空浮空平台。
移动平台、斜坡留到第二阶段，避免物理复杂度过早膨胀。

### 物理需求

- 平台顶部着陆与站立；离开边缘后下落；
- 单向平台：从下方穿过、从上方落上；
- 与现有动作兼容：二段跳、滑翔、下砸、冲刺、滑铲；
- 平台上的障碍与收集物绑定到平台坐标系。

### 路线与相机

- 高度分三层：地面、中层（约 y=450）、高层（约 y=300）；
- 第一版不做自由垂直相机，活动范围保持在画面内，只做有限的垂直跟随；
- 关卡生成从「障碍组合」升级为「关卡片段」：

```js
{ width, platforms: [], obstacles: [], pickups: [], route: 'ground_to_upper', difficulty }
```

### 可达性验收（每段必查）

1. 至少一条可通行路线；
2. 跳跃距离不超过角色能力上限；
3. 收集物不全部落在不可达位置；
4. 不连续生成无法反应的障碍；
5. 高难度片段之间有缓冲距离。

现有 `tools/verify_balance.py` 的数值审计思路要扩展到平台可达性。

## 内容层：把 AI 圈的事做成玩法

内容策略：**科普有趣 + 圈内吐槽各半，全部用 2025 年以来的真实事件做支撑**，
让玩家看到时能相视一笑。三层叙事（事实 / 演绎 / 玩法）与 `src` 核实约定见
`docs/story.md` 与 `src/memes.js` 文件头。

首批内容草案：

### 奇闻卡（收集后弹出）

| 卡片 | 现实背景（2025 起） | 玩法转化 |
|------|--------------------|---------|
| 推理模式 | DeepSeek-R1（2025-01）带起推理模型热潮 | 慢速、高倍率；思考气泡过多触发「想太久」减速 |
| 思考 / 非思考切换 | Qwen3（2025-04）支持双模式 | 两种模式适配不同路线，切换错误会过载 |
| 工具调用 | MCP 生态扩张（2024-11 起） | 工具站清除障碍，有冷却与失败概率 |
| 量化压缩 | 端侧小模型趋势 | 体积小、速度快，容错降低 |
| 缓存命中 | KV Cache 工程共识 | 重复路线获得加速 |
| 上下文溢出 | 长对话截断的日常 | 携带过多卡片触发视野干扰 |

新增条目一律先进 `src/memes.js` 并写 `src` 字段，文案里区隔「公开事实」与「游戏演绎」。

### 技术栈资源

Token 白饭（基础）、数据卡片（进度/分数）、推理火花（短时倍率）、
开源碎片（解锁）、安全徽章（抵挡一次）、AGI 核心碎片（稀有长期目标）。

### 工程化障碍

乱码 Bug、错误弹窗、无限循环代码块、算力服务器、幻觉气泡、
依赖地狱、限流门、Timeout 计时器。素材风格：圆角设备 + 信息牌 + 表情化故障，
不用尖刺金属和纯霓虹描边。

## 资源注册表

现在素材清单硬编码在 `src/game.js` 的 `PATHS`，`assets/manifest.json` 只提供碰撞箱。
方向：让 manifest 逐步描述素材的尺寸、碰撞箱、类型、所属分区、主题标签与可选项，
新增内容尽量只加资源与配置。保留现有机制：WebP→PNG 回退、可选素材降级、离线碰撞箱审计。

## 分期计划

| 阶段 | 内容 | 验收标准 |
|------|------|---------|
| 0 设计冻结 | 色板、平台高度、收集物与障碍分类（本文） | 团队对方向无异议，改造有基准文档 |
| 1 Vertical Slice：「AI 晨光城区」 | 明亮天空城市背景、三层平台、三种资源、四种障碍、新版 HUD | 连续游玩 3–5 分钟；上下两条路线清晰；平台碰撞稳定；桌面与横屏手机可玩；暂停/失败/重开无回归 |
| 2 内容与视觉扩展 | 正式背景、平台样式、更多障碍与收集物、奇闻卡系统 | ≥3 种赛道节奏、≥4 类障碍、≥3 类收集物；缺图仍可降级运行 |
| 3 系统拆分与 HUD 完善 | 拆出 world / physics / director / renderer / asset / hud | 新增内容只需数据配置；HUD 不频繁重建；商店、事件、暂停无回归 |
| 4 五大分区与长期平衡 | 分区主题化、路线分支、挑战段、资源经济 | 长跑 20 分钟无可达性事故；各分区视觉与玩法可区分 |

顺序原则：**先验证平台手感，再铺美术**。不要先换漂亮背景再补玩法，
否则会出现画面好看但路线不好玩、资源没意义的返工。

## 保留与重构清单

保留（已验证可用）：

- Vanilla Canvas + DOM HUD，不引入框架；
- 1280×720 虚拟画布、DPR 适配、固定时间步（120Hz）；
- 输入系统、移动端控制区、暂停 / 商店状态机；
- 粒子、飘字、屏幕震动、音频合成；
- manifest 碰撞箱机制、PNG/WebP 回退、可选素材降级；
- 分区 / 事件 / 技能数据与 `src` 核实约定。

必须重构：

- World/Surface：单一地面线 → 平台数组；
- Physics/Collision：障碍 AABB → 平台着陆 + 伤害体 + 拾取三类；
- Level Director：障碍组合 → 带可达性审计的关卡片段；
- Renderer/Camera：增加有限的垂直跟随与分层绘制；
- Asset Registry：注册表驱动替代硬编码 `PATHS`；
- HUD：统一 `hudState` 数据层，替换散落的 DOM 操作。
